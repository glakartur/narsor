# NARSOR-1124-001 — Dyrygent: „Argument list too long (os error 7)”

Status: **naprawiono błąd E2BIG** (harness `claude-code`). Dwie prośby
z ticketu to nowe funkcje. Te prośby wymagają decyzji (patrz „Decyzje do
podjęcia”).

## Objaw

Zakładka *Dyrygent* w TUI pokazuje dla taska
`2bf25b947b4a43db9be083705b7d33fa` serię wpisów błędu (2026-11-23,
08:59–10:22):

```
· TECHNICZNE · Dyrygent · 2026-11-23 08:59:40
  Could not summarize the human gate: failed to start the agent harness 'claude'
  in /home/dev/narsor/.../workspace: Argument list too long (os error 7)
```

Każde zatrzymanie na bramce `human` daje nowy wpis błędu. Dyrygent nie
tworzy podsumowania bramki. Czat z dyrygentem używa tej samej ścieżki, więc
też może dać ten błąd.

## Przyczyna główna

`os error 7` to `E2BIG` z `execve`. Linux ogranicza **jeden** argument do
`MAX_ARG_STRLEN` = 131 072 B (128 KiB). Dyrygent przekazywał cały prompt
(z migawką taska) jako **jeden argument** linii poleceń.

Łańcuch (wyzwalacz → objaw):

1. Task zatrzymuje się na bramce `human`. Silnik kolejkuje żądanie
   podsumowania bramki (`crates/narsor-exec/src/conductor/chat.rs`,
   `gate_suspended`).
2. `HarnessInvoker::try_invoke` buduje migawkę i prompt
   (`crates/narsor-exec/src/conductor/invoke.rs:309-334`). Budżet migawki to
   `160 * 1024` B (`crates/narsor-exec/src/conductor/snapshot.rs:73`). Ten
   budżet jest **większy niż 128 KiB**. Sekcje „whole” (definicja workflow,
   payload żądania) nie są skracane. Dla długiego taska prompt jest większy
   niż 128 KiB.
3. Adapter `claude-code` dodawał prompt jako ostatni argument i ustawiał
   `stdin: None` (`crates/narsor-exec/src/engine/actions/harness/claude_code.rs`,
   przed poprawką linie 245–251).
4. `run_harness_process` (ścieżka dyrygenta) zawsze przekazywał
   `stdin_content = None`
   (`crates/narsor-exec/src/engine/actions/session/process.rs:51`).
5. `Command::spawn` → `execve` zwraca `E2BIG`. `spawn_error` tworzy komunikat
   „failed to start the agent harness …” (`process.rs:235`, `:526`).
6. `conclude_annotation` zapisuje błąd w czacie jako „Could not summarize
   the human gate: …” (`chat.rs:207`). Błąd nie jest ponawiany, więc każda
   kolejna bramka daje nowy wpis.

## Poprawka

- `crates/narsor-exec/src/engine/actions/harness/claude_code.rs:88-92`,
  `:251-262` — nowa stała `LONGEST_PROMPT_ARGUMENT` = 96 KiB. Gdy prompt jest
  dłuższy, adapter nie dodaje go do `args`, tylko ustawia
  `stdin: Some(prompt)`. `claude --print` bez argumentu promptu czyta prompt
  z stdin. Krótszy prompt: bez zmian (argument w argv).
- `crates/narsor-exec/src/engine/actions/session/process.rs:51-75` —
  `run_harness_process` ma nowy parametr `stdin_content` i przekazuje go do
  `run_harness_invocation`.
- `crates/narsor-exec/src/conductor/invoke.rs:363` — dyrygent przekazuje
  `command.stdin.as_deref()`.

Kroki agenta już przekazywały `invocation.stdin`
(`engine/actions/session.rs:330`). Poprawka adaptera naprawia więc także
kroki agenta z promptem > 96 KiB.

## Test regresji

- `tests/integration/conductor_invoke.rs` —
  `a_prompt_too_long_for_one_argument_reaches_claude_on_stdin`: żądanie
  z payloadem 200 KiB, harness `claude-code` (fałszywy). Test sprawdza, że
  dyrygent odpowiada, prompt jest w stdin, a żaden argument nie ma 128 KiB.
- `tests/fixtures/harness/fake_harness.sh` — fałszywy harness zapisuje stdin
  do `stdin.<n>` (gdy stdin nie jest terminalem).
- Przed poprawką (red): `Failed { error: "failed to start the agent harness
  '…/fake_harness.sh' in …/workspace: Argument list too long (os error 7)" }`
  — ten sam błąd co w tickecie.
- Po poprawce (green): `1 passed`.
- `cargo test --workspace`: wszystkie testy przechodzą oprócz
  `conductor_invoke::claude_runs_read_only_in_the_workspace_without_an_action_attempt`.
  Ten test nie przechodzi z powodu środowiska: sesja agenta działa w akcji
  narsor i dziedziczy `ORCHESTRATOR_ACTION_ID`. Bez tej zmiennej
  (`env -u ORCHESTRATOR_ACTION_ID`) wszystkie 33 testy `conductor_invoke`
  przechodzą. Ta wada nie jest związana z poprawką.
- Co test wykrywa: powrót promptu do argv; pominięcie stdin w ścieżce
  dyrygenta. Czego nie wykrywa: zachowania prawdziwego CLI `claude` przy
  prompcie z stdin.

## Ryzyka

- Prompt > 96 KiB idzie do prawdziwego `claude` przez stdin. Należy
  sprawdzić to na hoście z zainstalowaną wersją CLI (test używa fałszywego
  harnessu).
- `codex`, `opencode`, `github_copilot` nadal przekazują prompt w argv. Ten
  sam błąd może wystąpić dla promptu > 128 KiB. `codex exec -` czyta z stdin,
  ale `apply_extra_args` (`harness/mod.rs`) kotwiczy dodatkowe argumenty
  przy prompcie — wymaga osobnej zmiany.
- Dodatkowe argumenty operatora (`apply_extra_args`): gdy prompt jest
  w stdin, są dodawane na końcu `args`. Dla `claude` nie ma argumentu
  pozycyjnego, więc kolejność nie ma znaczenia.

## Sygnał zapobiegawczy (propozycja)

Log `warn` z długością promptu i nazwą harnessu, gdy prompt dyrygenta
przekracza 96 KiB. Ten log pokazałby przyczynę od razu.
